# النشر على GitHub Pages — خطوتي 🌍

الموقع **ساكن بالكامل** (لا سيرفر ولا قواعد بيانات): ٥٢٥ صفحة HTML + الأصوات والصور والخطوط.
لذلك يمكن نشره على GitHub Pages والحصول على **رابط دائم بلا أي رمز مرور**:
`https://aicoinvestai-a11y.github.io/ktwat/`

---

## ما جُهّز في المشروع

| الأمر | ماذا يفعل |
| --- | --- |
| `npm run export:pages` | تصدير كامل للنشر على **مسار فرعي** (`/ktwat/`) — وهذا ما يحتاجه GitHub Pages |
| `npm run export:static` | تصدير كامل للنشر على **نطاق جذري** (Netlify / Cloudflare Pages / أي استضافة ثابتة) |
| `npm run search-index` | يولّد فهرس البحث `public/search-index.json` (يُستخدم في صفحة البحث) |

كل أمر تصدير ينفّذ بعده `scripts/finish-export.mjs` الذي:

1. **يعوّض المسار الفرعي**: Next.js يضيف `basePath` إلى روابط الصفحات وملفات `_next`، لكن مسارات
   الوسائط المكتوبة في الشيفرة (`/audio/…`، `/images/…`، `/fonts/…`، `/icons/…`، `/sw.js`،
   `/manifest.webmanifest`، `/search-index.json`) تحتاج إضافة البادئة في ناتج البناء فقط.
   **بلا هذه الخطوة يفتح الموقع بلا تنسيق ولا صوت على Pages.**
2. **`.nojekyll`**: يمنع Jekyll من تجاهل مجلد `_next` (وإلا ضاع كل تنسيق الموقع).
3. **`404.html`**: صفحة الخطأ التي تخدمها الاستضافات الثابتة.
4. **ضبط ملف التطبيق**: `start_url` و`scope` إلى `/ktwat/` ليعمل تثبيت الموقع كتطبيق (PWA).
5. **تحقّق نهائي**: عدد الصفحات والأصوات والخطوط، ووجود البادئة فعلاً في `index.html`.

## حالة النشر الحالية (محدَّثة)

| البند | الحالة |
| --- | --- |
| فرع `gh-pages` | ✅ **مرفوع** (١٩٦٥ ملفاً — الموقع كامل: ٥٢٥ صفحة + الأصوات والصور والخطوط) |
| إعداد Pages في المستودع | ⚠️ **مضبوط على `main` — يحتاج تبديلاً إلى `gh-pages`** |
| الرابط | <https://aicoinvestai-a11y.github.io/ktwat/> يعرض حالياً صفحة README من فرع `main` (وليس الموقع) |

**السبب:** لوحة Pages في المستودع محفوظة على `main / (root)`، وفرع `main` يحتوي الكود المصدري لا الموقع المبني،
لذلك يظهر README فقط وتردّ بقية المسارات (مثل `/ktwat/guide/`) بـ404.

**الإصلاح (نقرتان):** تكفي فتح صفحات الفروع — راجع «خطوات النشر» أدناه.

## خطوات النشر (مرة واحدة)

### ١) ارفع فرع `gh-pages`

الفرع مُجهَّز محلياً؛ يحتاج فقط أمر رفع واحد (بصلاحية كتابة على المستودع).

```bash
# من جهازك، بعد استنساخ المشروع
cd ktwat
npm ci && npm run export:pages
cd out
git init && git add -A && git commit -m "نشر موقع خطوتي"
git push --force "https://github.com/aicoinvestai-a11y/ktwat.git" HEAD:gh-pages
```

### ٢) فعّل Pages (٣ نقرات)

1. افتح <https://github.com/aicoinvestai-a11y/ktwat/settings/pages>
2. **Source** → `Deploy from a branch`
3. **Branch** → `gh-pages` • المجلد `/ (root)` → **Save**

خلال دقيقة إلى دقيقتين يصبح الرابط جاهزاً: **<https://aicoinvestai-a11y.github.io/ktwat/>**

## التحديث لاحقاً بعد أي تعديل

```bash
npm run verify && npm run export:pages      # فحص ثم تصدير
cd out && git add -A && git commit -m "تحديث" && git push --force <url> HEAD:gh-pages
```

الرفع بـ`--force` مقصود: فرع `gh-pages` يحتوي ناتج البناء فقط، ولا يُدرج فيه تاريخ المشروع.

## ملاحظات مهمة

- **الحدود**: GitHub Pages يسمح بموقع حتى ١ جيجابايت — حجم موقعنا ٨٨ م.ب، وأكبر ملف ١٫٧ م.ب (كلها داخل الحدود).
- **الصوت يعمل**: ملفات MP3 تُخدَّم كملفات ثابتة، ويخزّنها العامل (Service Worker) للعمل بلا إنترنت.
- **تخزين PWA**: عند تثبيت الموقع من رابط Pages، يعمل التخزين المحلي (المفضلة/الإعدادات) بشكل طبيعي
  لأنه مرتبط بالنطاق `aicoinvestai-a11y.github.io` — والمفضلة محفوظة في جهاز المستخدم فقط.
- **بلا رمز مرور**: عكس روابط المعاينة المؤقتة، رابط Pages عام ومباشر ولا ينتهي.
- **الصور والأصوات المرخّصة**: تُخدَّم من نفس الموقع (لا اتصال بأي خدمة خارجية) — حمل الشبكة الوحيد هو فتح الصفحة.
