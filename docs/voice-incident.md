# تقرير عطل الصوت وإصلاحه — خطوتي 🎧

**التاريخ:** 2026-09-24 • **الحالة:** مُصلَح، والأصل المُتلف محفوظ للمراجعة.

## ما حدث

عند معايرة الجَهارة المسموعة (رفع الصوت منخفض المستوى) استُعمل مرشّح `silenceremove` لتقليص
الصمت في بداية كل ملف ونهايته. هذا المرشّح — بصيغته الأولى:

```
silenceremove=start_periods=1:start_threshold=-50dB:stop_periods=1:stop_threshold=-50dB
```

— لا يقتصر على الصمت الطرفي، بل يعتبر **أول سكون داخلي** (فاصلة بين كلمتين) «نهاية الكلام»
فيقطع ما بعده. الأثر: كثير من الجمل بقيت الكلمة الأولى فقط (≈ 0.2 ثانية)، وبعض الملفات تعرّضت
للقطع أكثر من مرة مع كل معايرة جديدة.

قياسٌ على نغمة اختبار (0.5s نغمة + 0.4s سكون + 0.5s نغمة = 1.40s):

| المرشّح | الناتج |
| --- | --- |
| القديم | 0.64s ← قطع عند السكون الداخلي ✗ |
| الجديد | 1.40s ← يحفظ المحتوى ✓ |

## الإصلاح

1. **المرشّح الجديد** — تقليم من الطرفين فقط بلا لمس الوسط:
   `silenceremove=start…,areverse,silenceremove=start…,areverse`
2. **حارس أمان في المعايرة**: إذا قلّص التشذيب أكثر من 38% من مدة الملف، يُلغى التشذيب كاملاً
   ويُعاير الملف كما هو.
3. **حارس في الفحص الآلي** (`npm run verify`): أي ملف مسجّل مدته أقصر من نصّه (أقل من 62% من
   المدة المتوقعة = 0.35s + 0.075s لكل حرف) يُوقف النشر برسالة توجّه إلى سكربت الإصلاح.
4. **إعادة التوليد**: `npx tsx scripts/restore-voice.ts` يقرأ قائمة الجمل، يكشف المقطوع،
   ويعيد توليده من نصّه ثم يتحقق من مدته قبل القبول.

## مصدر الصوت الحالي

ملفات الجمل مُولَّدة **نطقاً آلياً عربياً** (صوت عربي فصيح واضح) — وهو المسموح في المشروع للنصوص
التعليمية، ولا يُستخدم إطلاقاً في القرآن (التلاوات تسجيلات حقيقية لقارئ معروف، ولم تُمسّ).

لإعادة توليد كل الجمل بصوت آخر (بشري أو مزوّد مدفوع):

```bash
ELEVENLABS_API_KEY=... VOICE_ID=... npm run voice-record -- --force
# أو OPENAI_API_KEY=... / TTS_ENDPOINT=...
npm run voice-normalize && npm run voice-manifest && npm run verify
```

## النسخ المحفوظة

`docs/voice-before-restore/` يحوي نسخة من كل ملف قبل استبداله (`<id>.mp3`) ونسخة ما بعد التوليد
(`<id>.new.mp3`) — للرجوع أو المقارنة، ولا تُستخدم في الموقع.
